# 1.0 decisions

This is the single register of what is decided and what is still open for 1.0. It replaces the open-decision list that
used to live in [decisions, risks and governance](08-decisions-risks-and-governance.md) and the alpha readiness audit
([web alpha readiness](web-alpha-readiness.md), kept as history). Update it when a decision is taken; link the
decision record when one exists.

Status: **Decided**, **Open** (needs the owner), **Out of 1.0 scope**.

## Decided

| Topic | Decision | Where |
| --- | --- | --- |
| Name, namespace, domain | Ombelle; `@ombelle-ui`; `ombelle-ui.vercel.app` | [README](../README.md) |
| Licence | MIT | `LICENSE` |
| Editions | Radix and Base UI, both shipped | [0005](decisions/0005-base-ui-edition.md) |
| Installer architecture | An independent installer, registry-format compatible | [0002](decisions/0002-registry-adapter.md) |
| Liquid glass | Stable family; accessibility not guaranteed; `design.transparency: "reduced"` restores the contrast guarantee. Never labelled experimental | [liquid glass](components/liquid-glass.md) |
| Snapshot identity and contract version | Published snapshots verify against their stored bytes | [0009](decisions/0009-snapshot-identity-and-contract-version.md) |
| CLI command set | The 1.0 CLI implements every command in the CLI specification, adds `update`, and allows `--overwrite` on managed files | [CLI specification](05-cli-specification.md) |
| React range | The CLI accepts the React range the templates support instead of the exact 19.3.1 pin | [CLI specification](05-cli-specification.md) |
| Upgrade route (PUB-01) | `update` ships in 1.0; delete and re-add stops being the documented route | [upgrading](upgrading-to-1.0.md) (written by the CLI work) |

## Open: need the owner

| ID | Question | Recommendation |
| --- | --- | --- |
| PUB-04 | The browser support statement | Publish "Chromium-based browsers, measured in Chromium on Windows and Linux CI; other engines are untested", and add engines before widening the claim |
| PUB-08 | Project file names: `ui-library.config.json`, `ui-preset.json` and `styles/ui-style.css` are generic and can collide with other tools; `.ombelle-*` names are branded | Keep the current names for 1.0 and freeze them (changing them later is breaking); decide before the freeze, not after |
| PUB-08 | Should the lock record the CLI version that wrote it (decision 0009, deferred)? | Yes; 1.0 is the cheapest moment to add the field |
| PUB-09 | **Token prefix.** Installed CSS writes `--control-height`, `--border-width`, `--shadow-x`, `--shadow-y`, `--motion-duration` and `--font-family` into the user's global stylesheet, while [docs/03](03-components-styles-accessibility.md) promises `--ui-control-height` and `--ui-` for additional tokens. These names cannot both be right | Either rename the code to `--ui-*` before 1.0 (a breaking change to installed bytes that `update` refreshes) or correct docs/03 to the unprefixed names. This work only declares the mismatch; it renames nothing |
| PUB-09 | Rename `data-data-table-*` attributes and the unprefixed keyframes (`progress-ring-spin`, `table-skeleton-pulse`, `toast-spinner-turn`) | Rename before 1.0 so they are not frozen by accident; until then they are declared internal in the [contract](1.0-public-contract.md) |
| PUB-10 | Do any templates derive from shadcn/ui source (rather than being written against its API)? If yes the MIT notice must travel with the installed files | Treated as derived until the author confirms otherwise: the [NOTICE](../NOTICE.md) says so |
| PUB-13 | Where internal plans and the 31 MB of evidence live | Move `docs/superpowers/` and screenshot evidence off the default branch's docs tree (see [documentation layout](#documentation-layout)) |
| PUB-05 | The compatibility rule for additive schema changes (new enum value, component, field) | Map unknown values to `UNSUPPORTED_RELEASE` with a "needs CLI ≥ x" next action, driven from the contracts package |
| CMP-06 | Schema `$id` base URL and titles | Decide with the schema publication |
| CAT-17 | Export `buttonVariants`? Add a "Differences from shadcn" list? | Add the list; decide the export with the freeze |
| SEC-03 | npm publishing from CI with provenance (trusted publishing) | Yes; see the [release procedure](cli-release.md#proposed-ci-publishing-owner-action) |
| SEC-05 | Show content hashes in official commands, or document trust on first use | Document trust on first use; show hashes for custom origins |
| SEC-08 | Production identifiers (Neon project and endpoint names, Vercel team slug) in public docs | Removed from this tree by this work; the history still contains them (see below) |
| RL-03, RL-06, RL-07 | Capacity runbook and retention, publishing only on an explicit action, shared IPv4 budget | Per the rate-limiting audit |
| 1.x support | How long each minor/major gets fixes | Latest minor of the current major only, until a second maintainer exists ([SECURITY.md](../SECURITY.md)) |
| Contract numbering | The 1.0 numbering of the contract release (`0.1.0` today) | Keep `0.1.0` as the catalog/compiler contract until its first incompatible change |

## Out of 1.0 scope

React Native and other native platforms, accounts, workspaces and monorepos, JavaScript (non-TSX) output, a commercial
model, a mobile device matrix, a team and budget plan, and agent skills.

## Documentation layout

User documentation is `README.md`, `docs/*.md`, `docs/components/` and `docs/decisions/`. Contributor evidence is under
`docs/evidence/`. `docs/superpowers/` holds agent-authored plans and specs from development; they are history, not
documentation, and nothing in the README links to them. Moving them and the screenshot evidence out of the default
branch is the PUB-13 decision above.
