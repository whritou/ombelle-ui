# 1.0 public contract

What Ombelle UI promises to keep stable from 1.0, and what it does not. Anything in the first part changes only with a
major version. Anything in the second part can change in a minor or patch release. **Open** marks a point the owner has
not decided; it is listed in [1.0 decisions](1.0-decisions.md) and is not part of the promise until decided.

The only published package is `@ombelle-ui/cli` (binary `ombelle`). Its JavaScript module is not an API, and the
`@ombelle/contracts`, `@ombelle/compiler` and `@ombelle/catalog` workspace packages are private and unpublished.

## 1. What 1.0 promises to keep stable

### CLI grammar

- The binary `ombelle` and the package `@ombelle-ui/cli`.
- The commands `init`, `add`, `add button --preset`, `add --recipe`, `theme add` and `update`, with the flags in the
  [CLI specification](05-cli-specification.md). Commands in the specification that are still marked proposed are not part
  of the promise until the specification calls them implemented.
- Three safety rules: `--yes` never bypasses a conflict, schema or compatibility failure; `--dry-run` writes nothing;
  a write from a non-TTY session needs `--yes`.

### Exit codes and diagnostics

- Exit codes 0 to 6: 0 success, 1 internal error, 2 invalid input, 3 unsupported project or release, 4 file conflict,
  5 resolution failure, 6 dependency failure.
- The diagnostic code names below. New codes may be added; existing names and their exit codes stay.

| Code | Exit | Meaning |
| --- | --- | --- |
| `INVALID_DATA` | 2 | Input failed schema or semantic validation |
| `UNKNOWN_COMPONENT` | 2 | Not a catalog component id |
| `STYLE_UNAVAILABLE` | 2 | The family does not support a component (no pair is unavailable today) |
| `UNSUPPORTED_PROJECT` | 3 | The project is outside the support window |
| `UNSUPPORTED_RELEASE` | 3 | The document needs a newer catalog or compiler release |
| `FILE_CONFLICT` | 4 | A planned file would overwrite edited, untracked or foreign source |
| `RESOLUTION_FAILURE` | 5 | A hosted code could not be resolved |
| `DEPENDENCY_FAILURE` | 6 | The package manager failed; files are rolled back |
| `INTERNAL_ERROR` | 1 | A bug; please report it |

`INVALID_REFERENCE` (a malformed code) is emitted today with exit 1 instead of 2; correcting it to 2 is a bug fix, not a
breaking change.

### `--json` records

- Field names and `status` values are stable; fields may be added. **Open:** an `outputVersion` field, typed notice
  codes and whether `changes[].afterContent` is part of the contract (PUB-06). Until decided, match on `status`, `code`
  and the documented fields only, never on `notices` or `managerWarning` text.

### Input documents

- Preset `schemaVersion` 1.x, recipe 1.0 and 2.0, snapshot 1.0 and 2.0. Every document valid under 1.0 installs with every
  1.x CLI, and a document that needs a newer CLI is refused with `UNSUPPORTED_RELEASE` or, until that mapping lands
  (**Open**, PUB-05), with `INVALID_DATA` naming the unknown value.
- Hash and canonicalization rules, and built-in presets frozen per `id@revision`. Existing hosted codes always resolve to
  the bytes they were published with.

### Project files

- The config, preset and lock files the CLI writes into a project (`ui-library.config.json`, `ui-preset.json`,
  `ui-library.lock.json` and the shared stylesheet `styles/ui-style.css`) keep their formats; a 1.x CLI reads every 1.x lock
  and refuses a newer lock with an upgrade message. **Open:** the file names themselves (PUB-08) and whether the lock
  records the CLI version that wrote it.

### Hosted codes

- The formats `ps_<32 hex>@1` and `rc_<32 hex>@1`. Published bytes never change, and a withdrawn code answers 410.
- The read routes `GET`/`HEAD /api/v1/{presets,recipes}/{id}/{revision}`, their response shape, headers and status codes
  as written in [Hosted API v1](hosted-api-v1.md).

### Installed source

This is the part of your project's files that Ombelle promises to keep stable:

- Component file names and the exported components with their documented props (see the component docs in
  `docs/components/`).
- The `data-slot` values and the state attributes each component page documents (the edition's own, for example
  `data-state` in Radix or `data-open` in Base UI).
- The semantic colour tokens (`--background`, `--foreground`, `--primary` and their pairs) and the `@theme inline`
  mapping.

**Open (PUB-09):** the names of the project design tokens `--control-height`, `--border-width`, `--shadow-x`,
`--shadow-y`, `--motion-duration` and `--font-family`. The installed CSS writes them unprefixed, while
[docs/03](03-components-styles-accessibility.md) documents a `--ui-` prefix. They are **not** promised until the owner
decides whether the code or the docs change. Plan for a rename.

Everything else in installed source is internal, including the exported helper functions inside component files
(`useDataTable`, `selectColumn`, the colour-picker helpers, `stepValue`, the code-block helpers and similar). Import them
at your own risk.

### Liquid glass

- A stable family whose accessibility is explicitly not guaranteed: text contrast depends on the background behind the
  glass, which the project cannot know.
- `design.transparency: "reduced"` restores the opaque form with the contrast guarantee.
- Removing the caveat later is not a breaking change. Removing the family or the reduced-transparency route is.

### Support window

- **Node:** 24 LTS, 24.19.0 or later.
- **React and Tailwind:** Tailwind v4; React and React DOM in the range the CLI accepts, stated in the
  [CLI specification](05-cli-specification.md) (decided to be a range, not the exact 19.3.1 pin; the exact range is
  recorded there when the CLI lands it).
- **Frameworks:** Vite React TSX and Next.js App Router TSX. No workspaces or monorepos.
- **Package managers:** npm, pnpm, Yarn Classic 1.22 and Yarn 4, and Bun 1.4.3.
- **Browsers:** **Open** (PUB-04). Evidence is Chromium only. Until a statement is published, only Chromium-based
  browsers are tested; liquid glass refraction is Chromium only.

## 2. What 1.0 does not promise

- **Installed bytes.** The exact bytes of installed source and CSS can change in a minor release; `update` refreshes
  them. Changes are listed in the CHANGELOG under "Installed source".
- **Internal names in installed source.** Internal helpers exported from component files, undocumented `data-*`
  attributes (including the repeated `data-data-table-*` names and the different meanings of `data-mode`), family-private
  custom properties (`--glass-*` internals, `--o-*` for Organic, `--rf-*` for Retro futurism, `--sidebar-*` and
  similar), and keyframe names (`progress-ring-spin`, `table-skeleton-pulse`, `toast-spinner-turn`). Base UI templates
  still use some `--radix-*` names, and `SidebarMenuButton` takes `asChild` in Radix and `render` in Base UI.
- **Dependency pins.** The exact versions of runtime dependencies the CLI installs (for example `lucide-react`).
- **CLI wording.** Human-readable output, prompts and notice text.
- **CLI internal state.** `.ombelle-operation.lock`, the `.ombelle-transactions/` folder, `plan.json` and `recovery.json`.
- **JavaScript APIs.** The CLI bundle's modules and the private `@ombelle/*` packages.
- **The hosted service beyond reads.** The POST publication routes are for the site's editors and are restricted by
  `Origin`. Quotas, capacity, uptime and retention beyond immutability are not promised. The website and editor URLs,
  apart from published code pages, can change.
- **Unimplemented commands.** Anything in the CLI specification still labelled "Not in 1.0".
- **Out-of-scope platforms.** React Native, accounts, workspaces and monorepos, and JavaScript (non-TSX) output.
