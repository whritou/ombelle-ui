# Registry adapter decision

20 October 2026. Tested shadcn 4.22.1 and its documented shadcn/registry API against a loopback registry and disposable pnpm Vite fixture. A generated Button item passed the upstream schema and installed component/utility source and CSS variables/rules. The app alias remained @/lib/utils. The operation changed package dependencies as part of installation; addRegistryItems has no documented dry-run/skip-dependency boundary matching Ombelle's strict plan contract.

Decision: keep the upstream schema and source/theme transport, but implement the narrow Vite/Next path/alias transformation and reviewed CSS merge in Ombelle. Production CLI code must not import the upstream probe. The probe remains a development integration check with only local reviewed registry payloads.

The selected primitive edition is Radix; the fixture upstream style identifier is radix-nova, accepted by the pinned API. Ombelle's styleFamily remains separate and never replaces components.json.style.

Audit update, 24 October 2026: the development-only shadcn toolchain still resolves braces 3.0.3 through fast-glob/micromatch. [GHSA-vfj7-8cjw-p6xm / CVE-2026-93687](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) was withdrawn on 23 October 2026 because it was not considered practically exploitable. It is no longer an active finding; no advisory is suppressed. The production CLI does not depend on shadcn/braces.

The current lockfile resolves fast-uri 3.1.9 (through Ajv, including the production contracts package) and body-parser 2.4.0 (through the development shadcn/Express chain), remediating the five active advisories returned before this update. Both updates fit their parent dependency ranges; no overrides or direct dependency upgrades are needed. Root installs continue to disable lifecycle scripts.

Audit update, 28 October 2026: the Task 11 workspace audit reports one current low-severity `deepmerge@4.3.1` finding, GHSA-gcqx-w48m-w2h4 / CVE-2026-93753. It is reached through the development-only `shadcn` / `@shadcn/registry` chain. The repository imports that adapter only for the local upstream compatibility integration probe; no production CLI path imports it. The advisory currently has no patched release. No exclusion, suppression, dependency change, or audit policy change was made; the measured quality gate remains failed until dependency remediation is available. See the [primary advisory](https://github.com/advisories/GHSA-gcqx-w48m-w2h4) and [Task 11 evidence](../evidence/immutable-preset-snapshots.md).

Audit update, 29 October 2026: `deepmerge` 4.3.1 is still its latest release and GHSA-gcqx-w48m-w2h4 still lists no patched version. The project accepts this one low-severity, development-only finding as a scoped exception: `pnpm-workspace.yaml` lists it under `auditConfig.ignoreGhsas`, and `pnpm audit` reports it as ignored. The exception must be reviewed by 30 November 2026. `tests/integration/audit-policy.test.ts` fails when the ignore list holds any other advisory, or once the review date has passed. At review, remove the entry if a patched release or a shadcn update removes `deepmerge` 4.3.1. Otherwise re-check the advisory and record a new date here and in the test. The same audit reported a new high-severity `systeminformation` finding, [GHSA-3f7j-7jwc-fxfj](https://github.com/advisories/GHSA-3f7j-7jwc-fxfj), through the development-only shadcn → `@dotenvx/dotenvx` chain. It was remediated by updating the lockfile to `systeminformation` 5.33.17, which is within the parent's `^5.22.11` range; it is not ignored.

Audit update, 31 October 2026: a new moderate `minimatch` finding, [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249), affects every version below 11.0.1. It is reached only through the development-only shadcn → `ts-morph` → `@ts-morph/common` chain. The lockfile resolves `minimatch` 10.2.6. Even the latest `@ts-morph/common` (0.29.0, through `shadcn` 4.23.0) still declares `^10.0.1`, so no in-range release is patched. Forcing `minimatch` 11 through an override would leave `ts-morph`'s declared range and was rejected. The finding joins the scoped `auditConfig.ignoreGhsas` exception under the same review date, 30 November 2026, and rules, and the policy test lists it. At review, remove it if `@ts-morph/common` accepts a patched `minimatch` or shadcn drops the chain.

`pnpm audit:workspace` runs a fresh `pnpm audit` against the configured registry for the current workspace lockfile, including production, development, optional, and transitive dependencies of the root, packages, and preview app. It applies no severity threshold and suppresses only the advisories listed under `auditConfig.ignoreGhsas` above. It returns a failing status for reported vulnerabilities or registry errors. CI runs it after the frozen install. This scope excludes standalone consumer trees, whose separately scoped audits remain part of the consumer matrix. A zero-finding result records the registry response at that time; it does not establish absence of unknown vulnerabilities, install-script risk, or a completed consumer/browser gate. Re-run before release.
