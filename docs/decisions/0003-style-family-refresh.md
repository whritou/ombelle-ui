# Style family refresh decision

4 November 2026. Release 0.4.0 refreshes the flat, minimalist and neo-brutalism style families (flat: tone surfaces, filled fields and a forced-colors boundary; minimalist: hairlines and underlined fields; neo-brutalism: key-press depth and stickers). 0.4.0 is a single release after 0.3.1: liquid glass changes in 0.4.0 relative to 0.3.0 (the refraction filter and the 3px default blur) come from 0.3.1, and this refresh does not alter liquid glass further.

Catalog 0.1.0 bytes change in place. The refresh does not bump the catalog or compiler compatibility version (both stay 0.1.0, schema 1.0), so the same catalog version now produces different bytes for `styles/ui-style.css`, `components/ui/*.css` and the scoped Button preset and recipe `button.css` of those three families. This follows the 0.3.0 precedent, which changed the same files in place for hover and pressed states. Each change is declared under `intentionalChanges` in `packages/compiler/test/fixtures/style-baseline.json`. Those entries document the changes; they are not enforced. What the tests enforce is the recorded hashes: the baseline test fails if the Button, Dialog and Input artifacts it compiles for flat, neo-brutalism and ombelle differ from `style-baseline.json`, and `stable-family-hashes.json` pins the per-artifact hashes of all stable families, so an undeclared change to a pinned artifact fails one of them until its hash is re-recorded.

Existing installs keep their files. Nothing rewrites a project's installed CSS or component source. A project picks up the refresh only when `theme add` or `add` is rerun against it, and the usual modified-file conflict checks apply to files the user edited.

Recipe IDs and revisions stay immutable. Hosted presets and Button recipes published before this release keep their codes, IDs and revisions; the stored data is unchanged and only the catalog bytes compiled from it differ. Output compiled with a published code before and after the upgrade can therefore differ in CSS.

The built-in presets of the three families change too: flat changes its palette and `borderWidthPx` 1 → 0, minimalist its palette and `radiusRem` 0.375 → 0.25, and neo-brutalism its palette and `borderWidthPx` 2 → 2.5. Their `presetHash`, `styles/ui-tokens.css` and the scoped Button scope hash therefore move, so re-adding an installed recipe or scoped preset built from them at the same revision now needs a revision bump.

The three `intentionalChanges` entries added for this refresh cover the `flat`, `minimalist` and `neo-brutalism` families, each for `styles/ui-style.css`, `components/ui/*.css`, the scoped Button preset and recipe `button.css`, `styles/ui-tokens.css` and the scoped Button preset and recipe `components/ui/button.tsx`, citing `docs/superpowers/plans/2026-11-04-editor-and-style-family-refresh.md`.

Verification at release preparation (4 November 2026, Windows 11, Node 24.19.0, pnpm 11.25.0 through corepack): `pnpm check:foundation` was not completed. It stopped at its `test:integration` step after `build:packages` and `test:unit` passed (91 files, 903 tests). The integration run had 30 failures that are environmental: no native Bun executable on this machine (`Cannot resolve a supported native bun executable`), `tar` cannot read a path on the D: drive (`Cannot connect to D: resolve failed`), and the upstream shadcn probe cannot find `pnpm` on PATH. The 36-consumer matrix, the browser contract and the evidence files were therefore not run or regenerated, and no evidence file changed. The gate must be rerun on a machine with Bun, npm, Yarn, registry access and browsers before the 0.4.0 evidence claims are extended.
