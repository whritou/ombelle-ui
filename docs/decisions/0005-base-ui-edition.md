# Base UI edition decision

7 November 2026. Supersedes the Radix-only primitive edition in [0002](0002-registry-adapter.md) for component editions; its registry-adapter decision is unchanged.

## Context

shadcn's pinned 4.22.1 offers Base UI component styles (`base-nova`, `base-vega`, `base-maia`, `base-lyra`, `base-mira`, `base-luma`, `base-sera`, `base-rhea`) next to the Radix ones. Projects created with them could apply only an Ombelle palette, and `add` rejected every component with "Component primitive edition is not supported". Every project created by `shadcn init`, Radix or Base UI, also stopped on shadcn's own `lib/utils.ts` and `components/ui/button.tsx`, which Ombelle treated as app-owned conflicts.

## Decision

- The CLI detects the project's edition from `components.json` (`radix` for `radix-nova`, `new-york` or no file; `base` for the pinned shadcn `base-*` styles) and records it in `ui-library.lock.json`. Editions are never mixed: once Ombelle components are installed, a different edition is a conflict.
- The catalog holds a reviewed Base UI template per Radix component in `packages/catalog/src/templates/base/`, built on `@base-ui/react` 1.9.0. Components without primitive imports share one template. All 24 components install in both editions.
- Base templates keep Ombelle's component API and `data-slot` values, and emit Radix's `data-state` attributes and `--radix-*` variables from Base UI state, so one reviewed stylesheet serves both editions. A browser parity test compares the computed styles of every slot between editions in each family, mode and state.
- `lib/utils.ts` generated by the pinned shadcn is adopted by hash. Any other existing file Ombelle does not own stays a conflict, resolved explicitly by overwriting it or by installing Ombelle's component beside it under `<components>/ombelle/` (prompt, or `--overwrite`/`--beside`; `--yes` alone never resolves it). A beside component uses `ombelle-` prefixed slots, and the shared rules for those slots move to the prefixed slots, so shadcn's own components receive no Ombelle slot rules.

## Alternatives rejected

- Rewriting Radix templates into Base UI at compile time: fragile, and the generated source would not be reviewed.
- An Ombelle runtime package hiding the primitive library: breaks "generated source has no Ombelle runtime dependency".
- Rewriting the shared CSS for Base UI, or keeping separate Base UI stylesheets: generated or duplicated CSS that drifts.

## Consequences

- Fourteen components have two sources. A change to shared state selectors must also be bridged in the Base templates; the parity test fails until it is.
- Base UI behaviour differs where the library does: disabled menu items stay focusable, and a mouse-clicked Radix tab shows a focus ring that a Base UI tab does not. Each component doc records its differences.
- Recipes (`add --recipe`) and component presets (`add button --preset`) remain Radix-only and fail with "Recipes and component presets aren't available for Base UI yet".
- Base UI consumers are verified by `pnpm prepare:base-consumers` and `pnpm test:base-consumers` (real installs, production Vite and Next.js builds, browser checks). They are not yet rows of the `check:foundation` consumer matrix.
