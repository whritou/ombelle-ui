## Verified local workflow

After initialization, `add button --preset <local.json>` accepts strict local UTF-8 preset JSON at most 256 KiB with exact catalog/compiler 0.1.0. Flat, minimalist, and neo brutalism are implemented. It creates a separate native `Button`, colocated scoped CSS, and usage under preset ID/revision paths. Importing that component loads its styling. See [commands, imports, ownership, and conflict rules](../foundation-local-usage.md#component-scoped-button-presets).

The 34 descriptors cover npm 6, pnpm 6, Yarn 6, and Bun 16 consumers. Each installs the three actual built-in preset identities: **34 × 3 = 102**. All framework builds use Node. Actual CLI runtimes are retained per descriptor, including the eight Bun-runtime cases; the other 26 use Node. Yarn Classic 1.22.22 and modern Yarn 4.18.1 cover the declared node-modules and Plug'n'Play layouts. Bun 1.4.3 covers text/binary locks and both CLI runtimes. Bun audits the whole graph; other managers audit production dependencies. These consumer audits do not establish a clean full development dependency audit; the existing upstream-registry development advisory remains documented in the [adapter decision](../decisions/0002-registry-adapter.md).

Each installation retains canonical compiler hashes, actual transformed source hashes, lock provenance, dry-run non-mutation, successful installation, repeat/no-op, changed-content and edited-source conflicts, and protected before/after hashes. Preset/configuration, global CSS/style pack, ordinary components/usages, recipes, package manifest, and manager lock stay preserved during scoped installation. The project lock adds scoped provenance. Shared utilities require matching recorded ownership and bytes. Identical repeats are no-ops; changed content under the same ID/revision, changed dark context, edited/untracked destinations, incompatible utility source, and invalid global provenance conflict even with `--yes`. Existing manager selection, script suppression, workspace rejection, and transaction/recovery boundaries apply.

## Browser measurement boundary

The **90** measured rows are **three host families × three selected preset families × two modes × five applications**: preview, pnpm Vite/Next.js, and npm Vite/Next.js. For equivalent measured artifacts, canonical compiler hashes align across all five applications, and each application's transformed source bytes are verified against that application's expected output. The fixture's loading toggle supplies native `disabled`/`aria-busy`; the preset Button has no recipe `loading` prop or `asChild` API.

Host isolation uses **a separate host page without component preset imports** for the reference module graph. It asserts that no component preset source/CSS requests occur there, then compares ordinary host styles in each real measured app. A separate regression proves an injected unscoped 123px Button radius is active and causes rejection. Cross-host screenshot parity uses a SHA-256 fingerprint of decoded pixels after dropping the lowest three bits of each RGB channel, which tolerates tiny edge-antialiasing differences; each exact PNG SHA-256 remains recorded, and each host still requires byte-identical screenshots across its applications. The validator requires the isolation method on every row and rejects incomplete, stale, duplicate, failed, or mismatched evidence. Old selector-filtered measurements cannot satisfy this gate.

Yarn/Bun have installation, source parity, audit, and Node production-build evidence only. Their browser behavior is outside this run. This component preset matrix does not establish native browser text zoom, screen-reader acceptance, human visual/accessibility review, or other browser engines.
