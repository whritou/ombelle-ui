## Implementation limits

Snapshots are schema-valid drafts; publication is not a quality review. Payloads are publicly readable by exact reference and do not expire automatically. Operator withdrawal blocks fresh API reads and replays, but does not revoke downloaded cache copies or source already installed by consumers. There is no account, ownership, alias, listing, recipe snapshot, self-service deletion, public endpoint, public CLI package, or deployment evidence.

SQLite requires the Node runtime and a persistent local volume. The service is explicitly initialized; importing, building, and request handling do not create or migrate the database. No Edge or ephemeral-hosting support is claimed. Public operation still needs a real domain, persistent storage, trusted-proxy setup, support/security contact, privacy/retention decisions, monitoring, backup/restore drills, and public CLI distribution.

The cache checks its private owner boundary and uses an exclusive temporary file, fsync, atomic no-clobber hard link, bounded admission/read size, and only evicts validated owned entries. Unknown/corrupt entries remain untouched and may cause safe admission failure. If hard links are unsupported, a successful install remains successful but emits a cache warning. On Windows, ACL inspection is read-only and missing inspection fails closed; it does not modify ACLs. Ancestor checks do not provide an openat/renameat guarantee against a hostile same-user or administrator concurrently swapping an ancestor. Windows junction and external hard-link tests were exercised; a real Unix symlink branch was not measured on this Windows host, and the real file symlink case returned EPERM even when escalated.

The quality report does not establish hosted CI, production deployment, native browser text zoom, human/screen-reader review, broad browser support, or availability of a deployed public service.
