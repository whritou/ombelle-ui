# Specimen audit

The specimen audit measures every catalog component as a project installs it, in every style family, edition and colour mode. It fails only on measured defects. Screenshots are saved for review and never compared against stored images. Design: [verification harness](../superpowers/specs/2026-11-09-verification-harness-design.md).

## What is measured

The audit pages are generated by `pnpm generate:preview` at `/audit/<family>/<edition>/?mode=light|dark`. Each starts from what `init` installs, the edition's tokens and shared styles, and loads no editor CSS.

- **Radix pages** render the 28 component recipes as `add --recipe` installs them. Each is the component editor's starting draft, pinned to the family's built-in preset (`builtin-liquid-glass` for glass) and rendered from its scoped primitives and recipe CSS. Button has no catalog recipe, so it renders from the ordinary Radix edition.
- **Base pages** render the 29 ordinary Base UI components with the same content, because recipes are Radix-only. Base Toast is shown through its manager API, as the catalog's Base usage example does.

Glass pages draw the backdrop the editors use for that preset and mode.

Before measuring, the suite opens every overlay with its real trigger. Tooltip is opened by keyboard Tab. Each overlay is then closed with Escape, and the suite checks that focus returns to the trigger.

| Check | What fails | Criterion |
| --- | --- | --- |
| Overflow | Text past its box; content squeezed by a box that clips it (`overflow: hidden` or `clip`) | WCAG 1.4.10, 1.4.12 |
| Clipping | A visible shadow or outline cut by an ancestor that clips (overflow, `clip-path`, `contain: paint`), also while the control is focused | WCAG 2.4.7, 1.4.11 |
| Spacing | A `label[for]` less than 4px from its control, beside or above | Readability of form labels |
| Focus visible | Fewer pixels changing by at least 3:1 between unfocused and focused than 90 percent of a 1px outline. List and menu items are reached with arrow keys | WCAG 2.4.7, 1.4.11 |
| Target size | An interactive target under 24×24 CSS px that is crowded by another target | WCAG 2.5.8, with its spacing exception |
| Forced colors | Light mode with `forced-colors: active`: a focused control shows no outline, a bordered surface loses its border, a backdrop filter remains, or text is transparent | WCAG 1.4.11 under forced colors |
| Axe | Any violation of the `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` and `wcag22aa` rules | WCAG 2.2 A and AA rules axe covers |

The self-tests in `tests/e2e/specimen-audit-checks.spec.ts` plant each defect next to a clean copy. Each check must report the defect and nothing on the clean copy.

Static checks run outside the browser:

- `pnpm build:packages` fails on a catalog style rule that names no slot or component marker, or that names an unknown slot.
- `packages/compiler/test/recipe-shadowing.test.ts` fails when a generated recipe declares a name that shadows the scope its primitives rely on. This was the Table Head bug.

## Defects found and fixed

| Defect | Where | Fix |
| --- | --- | --- |
| Label flush against its control | Checkbox, Switch, Label, Native Select recipes (all families). Reported by the user, then measured by the new spacing check | Recipe specimens lay out label and control with a gap (`590fc9a`) |
| Highlighted option or item had no 3:1 indicator; the background tint alone was too faint | Select and Dropdown Menu, both editions, every family | Inset ring in `--ring` (`f36b492`, `7280c33`) |
| Focus ring near-white on yellow in dark mode | neo-brutalism Accordion trigger, Dialog close | Ring inside the control, in its text colour (`4742abe`, `7280c33`) |
| Focus ring matched the checked option's background in dark mode | neo-brutalism Radio item (Base UI) | Ring in the option's text colour (`7280c33`) |
| Toast shadow cut by its scrolling viewport | flat, minimalist Toast | Viewport padding holds the shadow (`4742abe`) |
| Indicator glow always cut by the clipped track | liquid-glass Progress | Light drawn inside the indicator (`4742abe`) |

Fixes to the shared neo-brutalism `ui-style.css` mean existing neo-brutalism projects are asked to run `theme add` on their next `add`.

## Limits

- Chromium only. No Firefox or Safari run.
- The built-in presets only. A custom preset, a starting preset other than `builtin-liquid-glass`, or arbitrary overrides need their own checks.
- No NVDA, VoiceOver or other screen reader. The [manual review](../accessibility-review.md) is still required.
- No native browser text zoom at 200 percent, and no 320px reflow run.
- No consuming application. A project's own layout, content and backdrop can introduce defects the specimens do not have.
- Focus visibility is measured on pixels at device scale factor 1. It does not judge whether an indicator is easy to notice, only that it changes enough pixels by 3:1.
