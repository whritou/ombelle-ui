# Calendar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Calendar, with a DatePicker part, to the catalog in both editions and all five families, with a recipe, and use it in the preview scenes.

**Architecture:** Both editions wrap react-day-picker's `DayPicker`. Each part gets its `data-slot` through DayPicker's `components` prop, and a custom `Day` turns its range modifiers into data attributes. The Radix and Base UI templates differ only in the DatePicker's popover. Everything else follows sub-project 4 (branch `feat/overlays-search-073`): contract id and schema branch, templates and generated per-family styles, specimen and gating, scenes and fixtures, audit and docs.

**Tech Stack:**
- TypeScript ES modules, React 19.
- react-day-picker 10.0.2, date-fns 4.4.0, @date-fns/tz 1.5.0.
- Radix edition: `@radix-ui/react-popover` 1.3.1. Base UI edition: Base UI Popover (`@base-ui/react` 1.9.0).
- Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-10-calendar-design.md`

## Review Focus

- **A time zone west of UTC:** choosing the 12th in `America/Los_Angeles` submits `2026-11-12`, never the 11th. Task 4 pins this with a Playwright `timezoneId` test.
- **A DatePicker value changed from outside** (a reset button): the trigger shows the new date, or the placeholder, at once. Task 4 pins this with a fixture "Clear" button.
- **Range clicks in reverse order:** clicking the 18th, then the 12th, gives 12–18. Task 4 pins it.
- **Escape inside a DatePicker opened within a Dialog** closes only the picker, and focus returns to its trigger, inside the still-open dialog. Task 4 pins it with a fixture DatePicker in a Dialog.
- **Disabled days:** with past days disabled, the 9th cannot be chosen by click or by keyboard. Task 4 pins it.

**Interfaces (both templates export the same names):**
- **Helpers:**
  - `toIsoDate(date: Date): string` returns the local `YYYY-MM-DD`.
  - `fromIsoDate(text: string): Date | undefined` returns a local date at 12:00; an impossible date returns undefined.
  - `formatDate(value: Date | { from?: Date; to?: Date } | undefined, options?: Intl.DateTimeFormatOptions, locale?: string): string` returns `''` for undefined and uses `formatRange` for a complete range.
- **`Calendar(props: React.ComponentProps<typeof DayPicker>)`:**
  - Defaults: `showOutsideDays` true and `weekStartsOn` 0.
  - `components` gives every part its slot: `calendar` (Root), `calendar-months`, `calendar-month`, `calendar-nav`, `calendar-previous`, `calendar-next`, `calendar-caption`, `calendar-grid`, `calendar-weekdays`, `calendar-weekday`, `calendar-week`, `calendar-day` and `calendar-day-button`.
  - `Chevron` draws lucide `ChevronLeft` or `ChevronRight` with `aria-hidden`.
  - The custom `Day` sets `data-range-start`, `data-range-middle` and `data-range-end` from `modifiers.range_start`, `range_middle` and `range_end`. react-day-picker sets only classes for these.
- **`DatePicker(props)`:**
  - Props: `mode?: 'single' | 'range'`, `value`, `defaultValue`, `onValueChange`, `placeholder = 'Choose a date'`, `format = { dateStyle: 'medium' }`, `locale?: string`, `disabled?`, `name?`, `id?`, `aria-label?`, `aria-labelledby?`, plus `calendar?: Omit<CalendarProps, 'mode' | 'selected' | 'onSelect'>`.
  - Slots: `date-picker` (root), `date-picker-trigger` (a button with lucide `CalendarIcon` and `data-placeholder` while empty) and `date-picker-content` (the popover content).
  - Hidden inputs are `name`, or `name-from` and `name-to` for a range.
  - Choosing closes the popover in single mode; a range closes once both ends are set. Closing returns focus to the trigger.
  - Opening focuses the chosen day, or today, through DayPicker's `autoFocus`.
  - The trigger text always comes from the current value, so a change from outside shows at once.
