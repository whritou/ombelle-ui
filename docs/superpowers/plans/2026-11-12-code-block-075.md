# Code Block (0.7.5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Code Block (`CodeBlock`, its parts, `CodeBlockCommand` and `highlightCode`) to the catalog in both editions and all five families, with a recipe. Then replace the website's own code block, command tabs and highlighter in the docs, the editors' artifact views and the Get code dialog.

**Architecture:**
- **Catalog:** follow the sub-project 2 plan (`docs/superpowers/plans/2026-11-12-editor-inputs-075.md`) end to end: contract id, schema branch and appearance part; self-contained templates and per-family styles; compiler specimen and install gating; preview and website registration; docs.
- **Highlighter:** `apps/www/src/editor/components/code-highlight.tsx` moves into the template between `// highlight:start` and `// highlight:end`. The Base template carries the same block, and a unit test keeps the two blocks byte-identical (as the colour maths block in Color Picker). Output changes only in its markers: `className="codeLine"` becomes `data-slot="code-block-line"`, and `className="tok-<kind>"` becomes `data-token="<kind>"`. `text` is added and emits line spans with no tokens.
- **Self-contained templates:** Code Block imports only the Tabs primitive (`@radix-ui/react-tabs`, or Base UI `Tabs`). It does not import the catalog Tabs component, and the tab row uses Code Block's own slots.
- **Parts, ruling on the spec:** the parts take explicit props and need no context, so they work in any layout. A custom layout needs a styled frame, so the template also exports `CodeBlockRoot` (the root `div` that `CodeBlock` renders). The spec is amended alongside this plan.
- **Three small additions to the spec's props, each needed by a website user:**
  - `CodeBlockCopy` takes `onCopied?(ok: boolean)`, so the artifact panel keeps its "Install copied." status line.
  - `CodeBlockCommand` takes `copyLabel` (default "Copy command"), so the Get code dialog keeps "Copy install command" beside its own primary "Copy command" button.
  - `CodeBlockCommand` takes `runners?: Partial<Record<PackageManager, string>>`, so the docs keep `yarn dlx --quiet` (the guides tell readers to keep `--quiet` with `--json`).
- **Token colours, ruling on the spec:** each family writes its token colours as literal `oklch()` values in slot-scoped custom properties (`--code-block-keyword`, …), computed once from the family preset's `--primary` as the board mixes it. A `color-mix()` with the live `--primary` could fall under 4.5:1 for a user preset with a dark primary; literals on a fixed dark surface cannot, and a unit test checks every one. Consumers can still override the properties.
- **Website:** `scripts/generate-www-ui.ts` compiles Code Block into `apps/www/src/generated/ui/` at build time, like Number Input and Color Picker.

**Tech Stack:**
- TypeScript ES modules and React 19.
- `@radix-ui/react-tabs` and Base UI 1.9.0 `Tabs`; both are already pinned. No icons: the board's Copy is a text pill.
- Next.js 16, Vitest and Playwright.

**Spec:** `docs/superpowers/specs/2026-11-12-code-block-075-design.md`

## Review Focus

- **The clipboard is missing or rejects** (an insecure origin, a denied permission). Expected: no unhandled rejection; the polite live region says "Copy failed"; the visible label stays "Copy"; `onCopied(false)` is called. Task 6 pins this with a rejecting stub and with `navigator.clipboard` deleted.
- **Source edge cases:** an empty string, a trailing newline, Windows `\r\n` line endings, tabs and a line of 400 characters. Expected: the text of the output equals the source in every language; an empty source renders one empty line; `\r\n` gives one line per `\n`; the long line scrolls inside the `pre`, not the page. Task 2 pins the text cases; Task 6 pins the scroll with a fixture and the audit's overflow check.
- **A `manager` or `defaultManager` not in `managers`,** or a custom `managers` list. Expected: the first manager in the list is selected and its command shown; the order of the tabs follows the list. Task 3 pins this in SSR.
- **Copy clicked twice within 1.5 s, or the block unmounted while "Copied" shows.** Expected: the second click restarts the 1.5 s timer; unmounting clears it with no React warning. Task 6 pins the restart with Playwright's clock; Task 3 checks the effect cleanup clears the timer by code review of one `useEffect` return.
- **The Get code dialog while publishing or when install is unavailable.** Expected: there is no command yet, so the dialog shows its status text in the old `pre` and no package-manager tabs; the tabs appear once the command is ready, with the stored manager selected. Task 7 pins this in the editor e2e.
