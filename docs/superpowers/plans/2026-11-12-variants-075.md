> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the 0.7.5 board variants to Checkbox, Switch, Progress and Popover (batch 4a), then to Dialog, Alert Dialog and Breadcrumb (batch 4b), in both editions and all five families, with recipe fields, and use them in the website editors. Every default stays.

**Architecture:**
- **Conventions:** the 0.7.3 variant plans (`docs/superpowers/plans/2026-11-10-variants-basics.md`, `2026-11-11-variants-more.md`) apply:
  - optional props that set `data-*` attributes, or new parts with their own `data-slot`;
  - CSS appended by a scratchpad generator, `gen-variants-075.mjs`, between `/* 0.7.5 variants */` markers;
  - recipe fields in `schemas/`, specimens in `recipe-specimen.ts`, a CLI gate in `install-command.ts`.
- **Delivery:** the 0.7.5 sub-project plans (`2026-11-12-primitives-075.md`, `2026-11-12-editor-inputs-075.md`) apply: size baseline first, website swaps measured against the 10 kB limit, specimen audit, board comparison, evidence file, docs, browser case counts.
- **Two batches, two branches:** Tasks 1–8 are batch 4a on this worktree's branch. Tasks 9–15 are batch 4b on a branch created from 4a's last commit. Each batch ends with its own audit, evidence and docs, so each can become its own PR.
- **Fixture and browser spec:** `VariantsScenario075` (section `data-testid="variants-075"`) in both edition scenarios is created in Task 2 and extended by each component task. Its cases live in `tests/e2e/variants-075.spec.ts`.

**Rulings on the spec** (the spec is amended alongside this plan):
- **Breadcrumb is self-contained.** Templates never import other catalog components, and the catalog has no component-to-component install (Code Block and Color Picker plans). So `breadcrumb.tsx` imports the menu primitive directly: `@radix-ui/react-dropdown-menu`, or Base UI `Menu` in a new `templates/base/breadcrumb.tsx`. It draws the menu under its own slots (`breadcrumb-menu`, `breadcrumb-menu-item`), with each family's Dropdown Menu rules repeated in `breadcrumb` CSS. Installing Breadcrumb installs the `@radix-ui/react-dropdown-menu` package, not the Dropdown Menu component.
- **Progress recipe fields are `showLabel` and `showValue`.** The `progress` recipe already has an integer `value` prop, so the spec's boolean `value` cannot share the name; `label` is renamed to match.
- **New text fields are content, and the gate reads both props and content.** `checkbox.description` and `alert-dialog.confirmText` go in `content`. The 0.7.5 gate checks for the new keys in `props` and `content`, because older schemas reject either.
- **The Dialog body is a named region that is focusable only while it overflows.** A `div` with `aria-labelledby` needs a role, so `DialogBody` renders `role="region"`. It takes `tabIndex={0}` only while `data-overflowing` is set, as Scroll Area does, so a short body adds no empty Tab stop.
- **Selectors name one slot.** `DialogBody` also renders the marker `data-dialog-body`, so the layout rules read `[data-slot='dialog-content']:has(> [data-dialog-body])` and `[data-slot='dialog-footer']:is(:has(> [data-dialog-body][data-overflowing]) > *)`.
- **`AlertDialogMedia` draws its own icon.** With no children, it renders an inline SVG (a triangle for `destructive`, a circled "i" for `default`), as `BreadcrumbSeparator` does, so Alert Dialog gains no icon dependency.

**Interfaces (both editions):**
- `Progress` gains `size?: 'sm' | 'default' | 'lg'` and `tone?: 'default' | 'success' | 'warning' | 'destructive'`, set as `data-size` and `data-tone` only when not `default`.
- `ProgressLabel(props: React.ComponentProps<'span'>)` and `ProgressValue(props: Omit<React.ComponentProps<'span'>, 'children'> & { format?(value: number, max: number): string })`.
- `Progress` scans its children with `React.Children.toArray` for these two element types. With either present, it renders `<div data-slot="progress-field">` holding `<div data-slot="progress-header">` (label, then value) and the progressbar, which takes `aria-labelledby` set to the label's `useId()` id and `aria-valuetext` set to the value text. Without them, it renders today's output.
- `progressValueText(value: number | null | undefined, max: number, format?: (value: number, max: number) => string): string | undefined` is exported: `undefined` for `null`/`undefined`, otherwise `format(clamped, max)` or `` `${Math.round((clamped / max) * 100)}%` ``, with `clamped = Math.min(Math.max(value, 0), max)`.
- `ProgressValue` is `aria-hidden` and shows that text, read from a context `Progress` provides.
- Base UI uses `Progress.Label` and `Progress.Value` where they produce the same output; otherwise it writes them by hand like the Radix edition. The SSR output of both editions must match.
