# Variants (0.7.6, sections 01–06) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the 0.7.6 board variants 01 to 06 (Sheet `snapPoints`, `CardAction`, `SliderValue`, Progress and Meter `shape="circle"`, Code Block `diff`, `TooltipShortcut`) in both editions and all five families, with recipe fields behind a 0.7.6 gate. Every default stays.

**Architecture:**
- **Conventions:** the 0.7.5 variant plan (`docs/superpowers/plans/2026-11-12-variants-075.md`) applies:
  - optional props that set `data-*` attributes, or new parts with their own `data-slot`;
  - CSS appended by a scratchpad generator, `gen-variants-076.mjs`, between `/* 0.7.6 variants */` and `/* end 0.7.6 variants */` markers;
  - recipe fields in `schemas/`, specimens in `recipe-specimen.ts`, a CLI gate in `install-command.ts`.
- **Self-contained templates:** a part that looks like another catalog component (the Slider's number input, the Tooltip's key caps, the Card action button) draws that look in its own stylesheet under its own slot. No template imports another catalog component.
- **Fixture and browser spec:** `VariantsScenario076` (section `data-testid="variants-076"`) in both edition scenarios is created in Task 2 and extended by each component task. Its cases live in `tests/e2e/variants-076.spec.ts`. `ComponentsScenario076` and `components-076.spec.ts` belong to track 1 and are not touched.
- **One batch, one branch:** `feat/variants-076`. Section 07 (Carousel) is out of this plan; it waits for track 1's Carousel.
- **No website swaps.** The spec asks for none, so the website changes only in `install-command.ts` and the docs entries; First Load JS is not re-measured.

**Rulings on the spec:**
- **The Slider recipe field is `valueDisplay`** (`none`, `readout`, `editable`). The `slider` recipe already has an integer `value` prop, so the spec's `value` cannot share the name (as 0.7.5 renamed Progress's `label` and `value`).
- **The Tooltip recipe field is `content.shortcut`, a string of up to three keys joined by `+`** (`Ctrl+Z`, `Ctrl+Shift+P`), `maxLength` 40, empty meaning none. The component editor has no control that adds items to an absent string list; a text field works from absent. Validation rejects more than three keys and empty keys.
- **Both Slider editions write the `<output>` by hand.** Base UI's `Slider.Value` must sit inside `Slider.Root`, whose child `div` the family CSS styles as the control (`[data-slot='slider'] > div`), and a header there would break that rule and differ from Radix. As 0.7.5 ruled for Progress, Base UI uses the primitive part only where it produces the same output; here it does not.
- **The Progress ring shows its number only with `ProgressValue`.** `<Progress shape="circle" value={64}><ProgressValue /></Progress>` puts the readout inside the ring (not in the header); without `ProgressValue` the ring has no number (the board's button ring). Meter's ring always shows the rounded percentage.
- **Composition rules:** `sheet` `snapPoints` other than `none` needs `side: 'bottom'`; `slider` `valueDisplay: 'editable'` is rejected with `mode: 'range'`; `card` `action: true` is rejected with `mode: 'options'`; `code-block` `diff: true` is rejected with `mode: 'command'`. Each fails with a message naming the field.
- **Code Block diff markers are the first character only.** A line starting with `+` is added and one starting with `-` is removed; every other line is unchanged and copied as written. `diff` applies to the built-in highlighted output; with `children` (another highlighter) it sets nothing.

**Tech Stack:**
- TypeScript ES modules and React 19.
- Radix (`@radix-ui/react-dialog`, `-slider`, `-progress`, `-tooltip`, `-tabs`) and `@base-ui/react` 1.9.0, at their existing pins. No new dependency.
- Vitest and Playwright.

**Spec:** `docs/superpowers/specs/2026-11-13-variants-076-design.md`

- **A snap sheet dragged, released, then reopened.** Expected: a release between two points settles on the nearer one; a release below 0.25 closes; reopening starts at the first snap point again (Base UI keeps `SheetContent` mounted, so the reset must restore the first point, not "follow content"); Down on the lowest point closes and returns focus to the trigger. Task 4 pins the arithmetic in unit tests of `stepValue` and the keys in the browser.
- **A range Slider with a `SliderValue`.** Expected: the readout reads `20 – 80` with both values formatted by index; `editable` on a range throws no error at runtime and renders the readout instead (the recipe rule rejects it; a hand-written one degrades). Task 4 pins it in SSR.
- **A diff whose unchanged lines start with `-`** (a CSS custom property at column 0, `--radius: 4px`). Expected: by the ruling, it is a removed line; the docs say to indent unchanged lines or prefix them with a space. A CRLF diff keeps its `\r` out of the markers and the copy text has the same line endings as the input. Task 6 pins both in unit tests of `diffLines` and `diffNewVersion`.
- **Shortcut keys in odd forms.** Expected: `ariaKeyShortcuts(['Ctrl', 'Z'])` is `Control+Z`, `['⌘', 'K']` is `Meta+K`, `['Cmd', 'Shift', 'p']` is `Meta+Shift+P`, `['Esc']` is `Escape`; the recipe `Ctrl++` (an empty key) and `A+B+C+D` are rejected. Task 7 pins them in unit tests, Task 1 the recipe rule.
