# Web alpha readiness

Audit dated 3 November 2026 of milestone M5 (pilot and web alpha) against acceptance criteria PR1–PR11 in the [product requirements](01-product-requirements.md#acceptance-criteria) and the [pilot release gate](07-delivery-plan.md#pilot-release-gate). This audit only reads the recorded evidence and the tests. It ran no tests or gates, so every status below rests on the environment named in the linked evidence. The PR11 row was later updated from a measured run, whose environment it names.

## Gaps that block a pilot

In priority order:

1. **Manual assistive-technology review (PR5).** Run and record keyboard, NVDA with Chrome and VoiceOver with Safari reviews for each of the 36 stable entries, or restrict the alpha's stable claim to what is reviewed. Add the missing axe scans for Card and the native form controls first; they are cheap and close an automated hole.
2. **Keyboard operability of both editors (PR8).** Add a keyboard-only Button editor flow with an axe scan, extend the preset-editor keyboard case to family change, colour controls, export and publication, and record a human keyboard pass of both hosted editors.
3. **Real existing-shadcn theme merge (PR11).** The merge itself is now proven locally on genuine `shadcn init` Vite and Next.js projects with pnpm (see PR11). What still blocks the advertised route: publish a CLI release with the workspace-settings and `tailwindcss: "^4"` fixes, since `0.2.1` rejects every stock shadcn project. Then decide whether a theme-only merge, which installs nothing, should still require exact React versions; the Vite template fails it. Also document or ease the `lib/utils.ts` reconciliation that the first `add <component>` needs on a shadcn project.
4. **Published-package journeys for pnpm, Yarn and Bun (PR10).** Apply `init`, `add`, `theme add` and a local-edit conflict through `pnpm dlx`, `yarn dlx` (outside quarantine) and `bun x` with `0.2.1`, as was done for `npx`, and record them. Decide and document the Yarn Classic route.
5. **Glass decision.** Implement the experimental entries with visible limitations, or descope glass from the alpha in the product requirements before the pilot.
6. **A minimal catalog surface (PR9 and first release scope).** Pilot users need somewhere to see the stable/experimental/unavailable matrix and the native-control versus React Native distinction. Showing pnpm, Yarn and Bun commands in export panels belongs to the same change (PR7).

Not blocking a pilot, but owed before calling PR1–PR11 passed for the alpha: the cross-browser range in the [validation matrix](07-delivery-plan.md#validation-matrix) (Firefox, Safari, previous majors) for PR2 and PR5, a macOS run of the published CLI, export for components beyond Button (PR7), and an offline build of an app installed by the published package (PR1).
